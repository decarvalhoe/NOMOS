## Purpose

Control changes to code, schemas, docs, references, corpus profiles, validation assets and release evidence.

## Controlled Items

- source code;
- CUE/JSON/YAML schemas;
- workflows and CI policies;
- regulated documents;
- templates;
- external reference register;
- control matrix;
- validation protocols and reports;
- release bundles;
- generated evidence artifacts.

## Change Procedure

1. Open issue or PR with change rationale.
2. Identify intended-use and risk impact.
3. Update requirements/control matrix if needed.
4. Implement change.
5. Run relevant verification.
6. Record evidence.
7. Review and approve according to risk.
8. Update release bundle and public claim boundary.

Critical changes cannot bypass PR review.
