# Validation Checklist — `ai-rag` Domain Pack

Completed once per customer environment install. Signed by the
customer-side accountable owner before the pack is treated as
operational.

## 0. Identity

- **Pack id:** `ai-rag`
- **Pack version:** alpha-0.1
- **Customer / deployment:** replace_with_customer_or_deployment_id
- **Environment:** replace_with_env (for example, dev / staging /
  production)
- **Date:** replace_with_iso_date
- **Accountable owner (customer side):** replace_with_owner_role_and_name

## 1. Prerequisites

- [ ] Nomos baseline at `v0.1.0-alpha` is installed.
- [ ] Customer-integration checklist
  ([`templates/regulated/customer-integration-checklist.md`](../../../../templates/regulated/customer-integration-checklist.md))
  is filled in, signed, and stored under the customer's document
  control. The AI/RAG scope row is populated.
- [ ] Intended-use record names the AI/RAG scope, the model(s) and
  provider(s) in scope, the data classification handled, and the
  customer-side accountable owner.
- [ ] Supplier qualification record covers Nomos at the supported
  version under the customer's QMS.

## 2. References

- [ ] `references/ai-rag.yaml` exists in the customer repository.
- [ ] Each row from the install guide section 2.1 has a matching entry
  in `references/ai-rag.yaml`.
- [ ] For every customer-acquired licensed reference: canonical id,
  title, customer-side storage path, and SHA-256 hash captured at
  intake.
- [ ] The pack's reference loader runs against `references/ai-rag.yaml`
  without error.

## 3. Workflow Configuration

- [ ] Pack workflow files (or the customer's adopted equivalent) are
  present under `.github/workflows/` or the customer-equivalent path.
- [ ] Branch protection on the protected branch lists the regulated
  docs gate as a required-status check.
- [ ] CODEOWNERS for `docs/regulated/ai-rag-governance/` and the
  pack's evidence directory routes approvals to the customer's
  quality and AI/RAG owners.
- [ ] Approval workflow at
  `docs/regulated/validation-pack/approval-workflow.yaml` references
  the pack's evidence directory or has been extended to.

## 4. AI/RAG Control Coverage

For the customer's adopted AI/RAG governance record (under
`docs/regulated/ai-rag-governance/`), confirm that each control below
is either present in the record with concrete evidence or explicitly
marked as not applicable with rationale.

- [ ] Deterministic extraction has precedence over LLM extraction.
- [ ] Generated claims cite source IDs and source hashes.
- [ ] Prompt-injection and unsafe-output cases are tested using the
  customer's prompt-injection corpus.
- [ ] Low-confidence output is routed to `needs_review` rather than
  treated as product law.
- [ ] Model, provider, and version are recorded for any unit produced
  with LLM assistance.
- [ ] Prompt templates are recorded when relevant.
- [ ] RAG answers preserve citations and the documented refusal
  behavior.
- [ ] Human review status is retained for critical or ambiguous units.

## 5. Outputs

- [ ] `.regulated-doc-gate/regulated-doc-gate-report.json` is
  generated by a green run of the regulated docs gate.
- [ ] The customer's AI/RAG governance record under
  `docs/regulated/ai-rag-governance/` carries the controlled-document
  markers (`document_id`, `version`, `status`, `effective_status`,
  `owner`, `approver`) and is referenced by the release-evidence
  bundle.
- [ ] No artefact carries an overclaim warning from the regulated
  docs gate.

## 6. Gates

- [ ] `python scripts/regulated_docs_gate.py` runs without error on a
  clean checkout.
- [ ] The grep loop from install guide section 6 reports no
  `MISSING:` line for the customer's adopted record.
- [ ] Both gates above are part of the customer's required-status
  checks.

## 7. Claim Boundary

- [ ] The customer's public communication about this install matches
  [`claim-boundary.md`](claim-boundary.md) and the project-wide
  [`docs/public-claim-boundary.md`](../../../public-claim-boundary.md).
- [ ] No marketing surface claims the pack as Part 11 compliant,
  FDA-validated-AI, EU AI Act conformity, "bias-free AI", or
  "guaranteed-safe AI".
- [ ] Conditional claims always carry the documented conditional
  clause (validation-checklist id and reference versions).

## 8. Rollback Drill

- [ ] Rollback path from install guide section 8 has been exercised
  at least once on this environment.
- [ ] Recovery on partial install has been documented for this
  environment.

## 9. Result

- **Result.** replace_with_pass / replace_with_fail
- **Open deviations.** replace_with_list_or_none.
- **Waivers.** replace_with_list_or_none. Each waiver records the
  controlled decision id under `docs/regulated/decisions/`.
- **Reviewer:** replace_with_role_and_name
- **Approval meaning.** Approval here records that the `ai-rag` pack
  is operational in the customer's environment as scoped above. It
  is not a regulator approval, a certification, a Part 11
  conformity decision, an EU AI Act conformity decision, or a
  validated-AI claim.
